# Procedural Sample — ZSDR90010 (Sales Order Status List)

Source of truth for every Procedural program generated by sc4sap. `main-program.abap` fixes the main program. The `zsdr90010*.abap` files fix the include layout: what goes in each include, in which order, with which FORM names.

Executors copy the skeleton and adapt identifiers, tables and fields. The business content (sales orders, delivery flow) is only an example.

## Files

| File | Include | Content |
|---|---|---|
| `main-program.abap` | `{PROG}` | Header block, `REPORT`, INCLUDE order t → c → s → o → i → a → f, event blocks delegating to FORMs |
| `zsdr90010t.abap` | `{PROG}T` | `TABLES` (SELECT-OPTIONS `FOR` only) → `CONSTANTS` (function codes, ALV handles) → `TYPES` (read buffers, ALV line types, `TY_ALV` bundle) → main data tables → `CLASS … DEFINITION DEFERRED` + receiver ref → ALV objects → one OK_CODE variable |
| `zsdr90010c.abap` | `{PROG}C` | `LCL_EVENT_HANDLER` — one instance per grid, keeps its handle, every method is one `PERFORM` |
| `zsdr90010s.abap` | `{PROG}S` | Block 1 criteria, block 2 options on one line (`COMMENT` + `POSITION`), block 3 layout variant `P_VAR` + batch flag `P_BAT` |
| `zsdr90010o.abap` | `{PROG}O` | PBO modules, one `PERFORM` each |
| `zsdr90010i.abap` | `{PROG}I` | PAI modules, one `PERFORM` each |
| `zsdr90010a.abap` | `{PROG}A` | ALV FORMs (see below) |
| `zsdr90010f.abap` | `{PROG}F` | Selection-screen FORMs → read / build list → END-OF-SELECTION / batch → screen 0100 PBO/PAI FORMs → utilities |
| `zsdr90010.screen_0100.abap` | screen 0100 | Flow logic + element / GUI status notes |

Field catalog rule: `../alv-sample/field-catalog-guide.abap` (SALV extraction + `CASE fieldname`). The `a` include applies it unchanged.

## ALV pattern (include `a`)

- Screen 0100: `CL_GUI_DOCKING_CONTAINER` → `CL_GUI_SPLITTER_CONTAINER` (2 rows) → header grid on top, item grid below. Item pane height 0 until an order is opened.
- Each grid has one `TY_ALV` bundle (handle, grid, variant, layout, fieldcat, sort, exclude). ALV FORMs take the bundle as one parameter and branch on `ps_alv-handle`.
- `INIT_ALV_0100`: first PBO builds containers and runs `SET_ALV_STRUCTURE_0100` per grid; later PBOs only `REFRESH_ALV`.
- `SET_ALV_STRUCTURE_0100` order: create grid → variant → layout → sort → toolbar exclude → field catalog → events → first display.
- `DISPLAY_ALV_0100`: a field symbol assigned to the grid's global outtab — one `set_table_for_first_display` call for all grids.
- ALV toolbar codes go to PAI through `cl_gui_cfw=>set_new_ok_code`. `USER_COMMAND_0100` is the single dispatcher.
- `FREE_ALV_0100` frees the docking container on exit, so the next `CALL SCREEN` rebuilds everything.

## Naming

- Screen-bound FORMs end with `_0100` (`INIT_ALV_0100`, `MODIFY_FCAT_HEAD_0100`). Utilities have no suffix (`CREATE_DOCKING_CONTAINER`, `CONVERT_FCAT_DATA_GRID`, `REFRESH_ALV`). See `../procedural-form-naming.md`.
- FORMs called from the main event blocks keep the names in `main-program.abap`: `SET_SCREEN`, `CHECK_COMMON_AUTHORITY`, `CHECK_SCREEN_INPUT`, `SET_SCREEN_OUTPUT`, `SET_SCREEN_VARIANT`, `START_OF_SELECTION`, `END_OF_SELECTION`, `BATCH_DATA_COLLECTION`.
- Globals `g*`, FORM parameters `p*` (`pt_`, `ps_`, `pv_`, `po_`), locals `l*`.

## Objects the sample assumes

- Screen 0100: OK_CODE field `NAME = GV_OKCODE`. No custom control.
- GUI status 0100: `BACK` / `EXIT` / `CANC` as exit commands (type E), application toolbar `REFRESH`, `CLOSE`. Title 0100.
- Text symbols (type I): `B01`–`B04`, `T01`–`T04`, `G01`–`G02`, `F01`–`F04`, `M01`–`M06`, `E01`–`E03`.
- Selection texts (type S): every `S_*` / `P_*` name in the `s` include.
- Messages use class `00` number `001` (`&1&2&3&4…`) with text symbols, so the sample needs no message class.

## When the program is smaller

- No screen: drop `o`, `i`, `c`, `a`, screen 0100; `END_OF_SELECTION` shows SALV like `BATCH_DATA_COLLECTION`.
- One grid: keep the `TY_ALV` bundle and the handle branches with one `WHEN`; use the docking container without the splitter.
- Editable grid: add `HANDLE_DATA_CHANGED` in `c`, `register_edit_event` in `SET_EVENT_0100`, and drop the edit buttons from `SET_TOOLBAR_EXCLUDE`.

Syntax level: ABAP 7.40 SP08+ (inline declarations, `VALUE`, `COND`, host variables). Lower releases: rewrite per `../abap-release-reference.md`.
